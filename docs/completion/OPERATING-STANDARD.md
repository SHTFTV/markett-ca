# Portfolio definition of DONE — version 2

This is the canonical MarkEtt completion contract, not a replacement publisher or site SOT. Every site retains its own approved audience, brand, factual/content/media policy, services, workflows and durable bot. GitHub is canonical source; Vercel is production hosting. Private source is sufficient. A live homepage, READY deployment, assigned agent, connector login, prepared code or queued job cannot establish operational completion.

`lib/operational-completion.mjs` is the executable authority. `evaluateCompletion(contract, evidence, {now})` returns a per-check matrix, blockers, separate frontend/deployed/configured/enabled states and `operationally_complete`. Missing, unknown, stale, blocked or mismatched required evidence means incomplete. Individual `task_completed` or article `done` receipts retain their task/publication scope and never certify a whole site.

Each site must pin a contract to its exact GitHub source revision and actual SOT/owner requirements. Every catalog check needs explicit applicability and its source. Universal checks cannot be excluded. Conditional checks require an actual site-specific non-applicability reason; an existing promised flow cannot be excluded. Publishing coverage includes ingestion, deduplication, generation, factual verification, media, sole-writer publication and live verification. Record each promised form, planner, download, API and other functional flow; include dedicated flow proof, not generic checkbox coverage. Unresolved applicability is a blocker, never permission to omit promised automation. The template deliberately starts unresolved.

Production proof must identify the site/repository/exact source commit, observer, time, actual scope and retained proof reference. Do not generate fixture receipts for production or use local tests as live proof. Supply a per-check freshness window no greater than seven days; 24 hours is the starting maximum for runtime monitoring. A changed source commit invalidates previous exact-commit receipts until verified. Deployment, configured credentials, enabled schedule and a successful native unattended run are separate facts. Distinguish native schedule from dispatch/manual, push and recovery. Desktop and phone require actual rendered artifacts and viewports covering branding, home, article, cards, crops and readability. HTTP200 cannot substitute.

Every required connection needs least-privilege configuration and a real functional test. Durable state includes receipts, idempotency and a sole-writer lease. A failed article/page/feed/image must be isolated: retain its exact reason and independently delivered alert until verified recovery; continue other eligible work in the SAME run; bound retries and backoff so bad work cannot starve good work. Distinguish a global credential/runtime outage from an individual hold. Recovery proof must include actual queue/feed execution where one item/feed fails and another succeeds in the same run, retained receipts/dedup/leases, and a later bounded retry without starvation. Validator regression fixtures prove the reporting gate only; they do not prove a site's queue implementation.

A cloud bot must load the latest approved versioned per-site SOT each job, recording loaded revision/hash, canonical source and execution receipt. A checked-in local SOT copy or central policy alone is insufficient. No duplicate publishers, schedules or writers. Coverage ledger records committed policy separately from deployed loading proof. Site-specific writers retain their repositories; missing paths/access/activation remain explicit blockers.

Google and Bing ownership and sitemap acceptance are separate from indexing. Unknown index count is null, never zero. Pending external indexing is reported pending; if actual indexing is required by the site's contract it blocks completion until its target is proved. Required IAM launch announcement must have a live receipt; reuse an existing verified announcement instead of duplicating it.

Company-original release imagery where appropriate, otherwise original clearly labelled illustration; no Shutterstock. Preserve the site's approved credit, resolution, relevance and crop policy. Do not introduce a blanket image registry gate or new manual approval for each routine article. Authorized automated editorial/factual verification operates under the existing SOT. No new purchases, access, services or activation scope follows from this standard. Never store credentials, lead contents or private account information in public reports.

## Site-owner consumption

Start from `docs/completion/contract.template.json` and the two JSON schemas in this directory. Vendor the validator pinned to a reviewed canonical MarkEtt commit into existing build/report entrypoints; record that pin in the site's SOT. Keep the actual site's SOT canonical in its own repo. `node scripts/completion/report.mjs records.json output-directory --require-complete` is the release/completion gate; it exits nonzero for incomplete records. A partial frontend deployment may continue if already authorized, but its report must retain `operationally_complete:false`. No artifact or test automatically authorizes publisher activation.

Canonical API reporting uses this same evaluator on every request, so receipts expire without a new deployment. Missing contracts across the known registry are explicitly incomplete. The scheduled existing portfolio audit also emits a matrix artifact; its successful HTTP task never upgrades site completion. Build/CI tests cover positive evidence and realistic missing-worker/forms/alerts, stale/manual-only runs, unknown indexing, missing applicability, wrong-site/revision receipts, missing rendered proof and failure-isolation evidence.

## Existing site-runtime adapter

`lib/site-job-standard.mjs` exports `executeSiteJob({site,jobId,sourceCommit,store,execute})`. Bind `store.latestApproved(site)` and `store.recordSotLoad(receipt)` to the site's existing durable approved SOT/receipt store. The approved object must include site, approved=true, revision, canonicalRef, content, SHA256 contentHash and operatingStandardVersion=2. This helper reloads on every invocation and rejects missing, unapproved, tampered or wrong-site rules. The existing sole publisher must call `assertStillApproved()` inside its existing commit boundary; changes force retry under current rules. This is a reusable runtime adapter, not a second scheduler, queue, publisher or proof of site adoption. The ledger must retain an adoption/loading blocker until each site actually deploys it or equivalent enforcement and supplies a real cloud load receipt.

Naturopaths event actor provisioning uses additive server-only `MARKETT_NATUROPATHS_EVENT_KEY`. The resulting fixed `naturopaths-site-bot` may emit only `task_completed`, `task_blocked`, `heartbeat` for exact domain `naturopaths.io`; it cannot emit `publication_verified`. Existing actors remain unchanged; collisions fail closed. No credential is provisioned by this code change.

## Version 2 — make access and a real workflow first

The required executable order is: (1) verified canonical GitHub repository and exact source-to-production connection; (2) securely connected, scoped and production-tested access for EVERY integration required by the actual site program; (3) one declared minimal REAL production workflow with durable receipt and verified result; (4) substantial dependent content/UI build or extension; (5) full operational completion verification. Missing credentials/integration tests surface before dependent work, never as an optional item after DONE. Use supported scoped OAuth, managed identity or tokens as appropriate; do not invent a raw-key requirement or reuse broad credentials.

`lib/site-build-gate.mjs` exports `evaluateBuildStages` and `authorizeBuildWork`. A contract declares actual `requiredIntegrations`, `minimalProductionFlow` and sourced `workUnits`. Exact `source`, `access:<integration-id>` and `minimal-production-workflow` receipts are required; saved secrets, connector logins and configuration do not pass. Source setup/independent audits may proceed within their declared scope; access setup requires the source link; the minimal production test requires access proofs; dependent build requires the minimal result. The CLI is `node scripts/completion/authorize-build.mjs site-record.json work-id`. Its nonzero exit blocks the dependent build. `site-package.template.json` provides the mandatory prebuild entrypoint while preserving the site's actual build command.

The original seven and three recent builds are tracked as ten incomplete current contracts. Unrecovered program scopes and access inventories remain explicit missing requirements, not invented services or fabricated historical passes. The205-row registry ledger requires v2; no existing healthy service is disabled by this retrofit. Per-site consumers must actually adopt the gate in their own canonical build and SOT before adoption is claimed. Prepared per-site append patches remain subject to existing source-owner/review holds.

## Page quality policy revision1 — every site and every bot

This requirement applies to every canonical site SOT and every bot's own canonical operating rules. The shared policy is not proof that those files or deployed consumers have changed. Preserve each site's audience, brands, finite campaign, sole writer, approvals and private workflows. Every actual job records site, canonical SOT source, approved revision, loaded content SHA256, exact source commit, quality-policy revision and run reference. Missing or mismatched policy prevents the affected publish.

Substantive editorial pages/posts require2000+ meaningful main-content words, real sourced reporting or analysis, and factual/editorial review. Do not add filler to reach a counter. Utility pages, privacy/legal terms and forms retain explicit sourced exemptions from the editorial word threshold; metadata, branding, accessibility and appropriate visual checks still apply. Previously short editorial formats require reconciliation by their existing owner with this new explicit instruction; do not silently invent an exception or rewrite old posts without scope review.

Every public page has its own appropriate Open Graph and Twitter/X card: page title, description, exact HTTPS URL, relevant image, type and card format. Do not repeat the homepage title/description/image on editorial pages. Verify actual image bytes/HTTP response and inspect desktop/phone social/article presentation, crop, relevance, polish and credit. Verify the branded favicon/icon declaration and actual asset. Company-original equipment imagery is preferred when available; otherwise follow the site's approved clearly-labelled original illustration policy. No Shutterstock. Visual taste, credit, substantive facts and relevance require attributable exact-page review, not just metadata booleans.

AEO/SEO/GEO/LLM readiness means readable substantive HTML, clear page headings and language, exact canonical URLs, appropriate structured article headline/author/publication dates, useful sourced context, internal discovery links and truthful page-specific metadata. Do not promise search indexing or AI inclusion from those technical checks; no forced FAQ or keyword padding. The actual page review records factual source and image-credit references.

`lib/page-quality-standard.mjs` inspects actual HTML, main-content word count, page-specific card values, image/icon checks and exact-page visual/editorial evidence. `scripts/completion/audit-pages.mjs input.json output.json` performs bounded read-only production fetches and actual image-byte checks, retaining each page failure independently. An audit without real visual/SOT review remains failed/unknown, not green. The publisher adapter exposes `assertPageReady(page)` and retains its per-page result through the existing durable `store.recordPageQuality` binding. Existing sole workers must call that guard inside their own leased/idempotent commit boundary and catch/retain individual failures so unrelated eligible items continue in the SAME run. This adapter is not a second publisher or scheduler.

A complete actual page inventory is required to claim whole-site page coverage. The completion evaluator requires current exact-site/repository/source-commit per-page receipts, with checked URL, card image and visual proof reference. Missing inventory or uninspected pages remain unknown.

Four Roles are independently inspectable: (1) existing working bot, canonical SOT load and durable queue/lease/idempotent execution; (2) visual checker with exact-page desktop/phone artifacts; (3) supervisor checking actual source/API/deployment/publication receipts; (4) an independent missed-heartbeat watchdog detecting silence of BOTH worker and supervisor, with an isolated injected failure, actual owner delivery and matching verified recovery. The same GitHub scheduler cannot prove external monitoring of its own silence. Bounded retries/backoff, credential health and legitimate GitHub/Vercel deployment identities remain mandatory. `lib/four-role-evidence.mjs` refuses stale, configured-only, same-scheduler or undelivered acceptance. A delivered alert must be actual delivery evidence; queue acceptance, stored issues, instructions and chats do not qualify.

The Command Center exposes per-site loaded SOT evidence, page/card checks, Four Roles status, timestamps and specific gaps. Central tests prove the validator only. Every site remains unverified for this revision until its reserved source owner adopts the policy/guard in the canonical SOT/runtime and supplies actual production receipts. Existing approval holds stay in force.

## Source-writing publication identity: runtime A → content/deployment B

A source-writing worker runs code at commit A and may legitimately create content commit B that Vercel deploys. Pin `contract.sourceCommit` (legacy scope alias) and `runtimeSourceCommit` to actual execution code A, not a continuously moving main branch. Record actual `deploymentSourceCommit` B separately. Never change the worker run's actual head SHA to B, and never pretend B executed the worker. Every role also records its own actual `observerSourceCommit` and `observerRunHeadSha` (for GitHub); a supervisor/watchdog may execute coordinator code C in its declared observer repository while checking the site transaction A→B. Its artifact scope remains runtime A. Raw provider verification must compare each observer run to its OWN observer head, not blindly to site deployment B.

`resolveSourceBinding(contract,evidence,{now,deploymentSourceCommit})` in `lib/publication-source-binding.mjs` accepts identical A/B directly. Different B requires declared `publicationMode: source-writing`, actual scoped `publicationWritePaths`, protected runtime/SOT paths and exact Vercel project identity. A fresh `publication-transaction` receipt must retain actual provider-verified GitHub compare A...B with ancestry and complete changed-file paths; actual site worker run/head A; actual declared-project Vercel deployment Git SHA B; and unchanged approved/loaded SOT hashes before and after commit. Any undeclared output, runtime/config/SOT change, wrong project/head, stale/held/failed receipt or absent provider verification keeps the binding unproven. This is a content transaction allowance, never a blanket code/SOT-change exception. Review actual runtime protected-path inventory rather than inventing safe paths.

Per-page evidence is scoped to runtime A but its rendered result/review `sourceCommit` is deployment B, with `runtimeSourceCommit: A`; its page inventory entry may declare B. Four-role receipts retain those two identities and their own observer head. Supervisor and watchdog still link the exact CURRENT worker and supervisor run references. The completion and prebuild evaluators expose and require source bindings; no relaxed most-recent-main equality is used.

For `assertPageReady`, the latest approved SOT envelope supplies `publicationSourceContract` (site/runtime A, project and actual output/protected paths). The caller supplies B and actual transaction evidence. The guard rejects missing linkage or a transaction policy hash different from the SOT this job actually loaded, retains the failed item, and permits independent correctly proven items to continue. A new code/SOT revision requires a fresh actual job under that revision; it cannot borrow the old A transaction.

EVERY role bot declares its canonical SOT reference in `contract.roleSotRefs`. Each actual role receipt must prove approved/loaded revision and SHA256 equality, matching source reference, quality policy version and freshness. Site-worker loading does not establish that the checker, supervisor or watchdog loaded its own rules.
