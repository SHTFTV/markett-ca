# Canonical connection evidence and onboarding

`connection-registry.json` is connection/owner metadata, not a replacement site SOT. The fixed four roles are imported from `lib/four-role-evidence.mjs`. Site purpose, sources, workflows and per-role instructions remain authoritative in each existing canonical site SOT. `workflow-connections.json` and `provider-connections.json` retain actual scoped provider reads with timestamps and source/project bindings. They do not certify business flows, publication, image quality or independent alert delivery.

Every canonical registry row receives a connection-state view, including sites with missing records. New rows are automatically included. Known repositories, existing provider projects, original database references, reserved executors and recovery routes persist; do not ask the user to rediscover these identities. Missing/stale evidence becomes unknown/blocked, never “not owned” or “billing unpaid” by inference. Application-purpose uncertainty is separate from provider access.

The executable API path `lib/connection-registry.mjs` joins the registry, owning SOT coverage, actual completion access receipts, runtime role observations and retained connection metadata. The canonical build-gate evaluator alone recognizes production functional access proofs. Connector login, permission metadata, READY deployment and configuration are separate observations. No secret value or customer data belongs in this registry; private source-conversation URLs stay with their owning executor. `/api/connection-state?site=<domain>` and the Four Roles breakdown expose owner/scope/dependencies, access observation, actual production execution time, age, exact blocker and recovery path.

The existing coordinator reloads the registry, adapters and connection records each invocation. It reuses known source/owner identities, probes declared public adapters, retains exact failures and retries other sites independently. It must not start a second publisher or replace a functioning backend. No mandatory Supabase dependency is added: only an actual site-program requirement can declare one. A missing original-project account is routed to its reserved recovery owner, not worked around with another tenant. A held schema/permission change remains held.

The publication audit is executable, bounded, same-site and read-only. Publication time is taken from actual article/feed publication metadata and a successful article request, never heartbeat, run time, sitemap lastmod, dateModified or a revised copyright date. Every registry row is checked in the initial audit; unknown publication time stays unknown. The coordinator rotates a small independent audit batch even when role retries are cooling down, so one blocked item does not postpone all other site checks. The API reevaluates the two-hour age on every read; actual role-run time and check time remain separate. An older post is not repaired by inventing, duplicating or redating content. A legitimate no-eligible-content state requires actual current producer evidence, not a successful generic check.

GitHub payment is user-reported completed. Retain actual latest workflow evidence per workflow and distinguish earlier failures from newer successes. Current provider execution demonstrates some checks working while actual publisher/endpoint/authorization failures remain site-specific. Do not change payment, budgets or purchase services from this record.

Neither blocker authorizes a duplicate worker, new project or repeated source-history hunt.

Mining Minute site-specific requirement (2026-11-12): publish a new eligible post every five minutes (300 seconds), distinct from five-minute polling. The shared report uses this stricter target while retaining the two-hour portfolio fallback for other sites. Actual post timestamps determine the current gap; scheduler success never proves publication cadence. Missing publication dates stay unknown. Source, factual, media, rights and duplicate gates remain mandatory; do not fabricate, duplicate or redate posts to fill a gap. A missed target must expose actual producer no-eligible-content evidence or errors when available, and must remain a missed publication target even if no eligible content is legitimately available. The Mining owner retains its canonical site SOT, transferred Gemini roster and sole publisher; this shared requirement does not activate a competing writer.
