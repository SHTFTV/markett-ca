# Fixed Four Roles portfolio coordinator

Canonical inventory is the entire current `api/registry-data.js` registry, never a fixed row count. New rows enter the durable queue on the next native GitHub scheduled run. Removed domains and their failures remain retained as retired records pending reconciliation. First priority is The Mining Minute, LoveOurListings, Weddings; pending other sites precede cooled-down retries. A registrar listing is never a built-site or activation receipt.

Architecture is fixed: canonical GitHub source, Vercel hosting, actual public domain routing, preserved required forms/uploads/private backends and no legacy platform branding. Migration owners retain all cutovers. Hosting evidence needs exact repository, source commit, Vercel project/deployment, actual public domain check and timestamp. pSEO infrastructure/readiness, search ownership/sitemaps, and indexing remain separate assertions; none follows from Four Roles approval. No old host, parked page or unverified domain earns an approval.

The coordinator is portfolio management, not a fifth site role. Existing single writers retain publishing and activation. It executes bounded read-only adapters, retains failures and manages retries. It never dispatches a replacement publisher, clears a review hold, creates a paid service, moves DNS or infers missing site purpose. Existing native Actions is the runtime; the repository holds append-preserving queue checkpoints and leases. Each batch claims at most 30 sites, commits leases before execution, checkpoints final results, and times out in 12 minutes. Leases expire after 10 minutes for restart recovery. Per-site exceptions are isolated. Retry backoff is bounded at six hours; failures remain explicit rather than becoming success after exhausting retries. GitHub serializes queue commits with one concurrency group. This state queue coordinates evidence/implementation gaps; it does not claim to be the site's publication queue. Its durable storage restart proof does not establish a site's own deduplication/recovery.

`portfolio-rollout-status.json` contains the current queue, per-role retained blockers, exact run ID/URL/trigger/source commit and time. `portfolio-rollout-watchdog.json` is written by a separate job that checks coordinator silence without invoking the coordinator. Both use the same GitHub service: that check does NOT establish an external watchdog for a site's GitHub scheduler. Site watchdog receipts require distinct scheduler identities and actual silent-worker/supervisor detection. Native runs must be observed before unattended execution is claimed. No perpetual uptime claim follows from finite checks.

Only explicit site-owner adapters in `docs/rollout/adapters.json` can supply receipts. Existing publisher-status adapters record observations, never a role pass. A role evidence endpoint must be an approved exact-site HTTPS path without offsite redirects. Its packet is `{receipts:[...]}`; every receipt is bound to `check:role:<role>`, site, repository, current sourceCommit, production environment, synthetic=false, actor identity, scheduler identity, exact runRef/proofRef and actual observedAt. The runner checks the provider's actual successful completed run, source commit and timestamp against current canonical GitHub main. Unavailable scoped provider access is a blocker. A candidate's own `runtimeAttestation` is replaced by verification performed by this runner. Other execution providers require an explicitly implemented scoped verifier; generic assertion fields cannot pass them.

The fixed roles are worker, visual-checker, supervisor, independent-watchdog. `lib/portfolio-rollout.mjs` adds approval-chain dependencies to the canonical operating standard: native scheduled worker plus loaded SOT/hash, live result, deduplication, writer lease, real failure isolation and bounded retry; exact rendered desktop/phone page/image/card/readability/quality artifacts; supervision of the current worker run/result/heartbeat and actual failure detection; independent silent-supervisor detection/recovery plus actual delivered owner receipt. Missing, held, failed, future, stale or mismatched evidence stays red. Every role must match the same current source commit. Worker freshness cap is two hours, visual 24 hours, supervisor/watchdog 30 minutes; source changes invalidate earlier receipts. Tighter declared TTLs apply. The API and browser re-evaluate expiry, so a saved green bit cannot persist.

A central owner-delivery receipt must come from the existing authorized monitor delivery integration, match the watchdog receipt and remain fresh. A site JSON assertion, queued event, successful send request, Action log, accepted cross-chat message or visible public dashboard is not genuine owner delivery. Current integration is absent: MARKETT_ALERT_WEBHOOK_URL/TOKEN/DESTINATION are not provisioned. The available local Codex tools expose no supported independently callable cloud ingress. This is an actual integration blocker; no alternative email/Slack/notification channel is silently selected. Initial source/adapter and hosting gaps remain red site by site. Actual site worker/visual/supervisor/watchdog deployments must be supplied by their owning integrations, not fabricated from this management loop.

The central delivery integration and source-standard owner remain authoritative. The shared `lib/four-role-evidence.mjs` validator is consumed when present; the approval chain adds tighter actual native-trigger, current dependency and expiry constraints. Local fixture tests demonstrate gate behavior only. No fixture becomes production state. Public projection contains no secrets, customer material, account contacts or raw exception content.
