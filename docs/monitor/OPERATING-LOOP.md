# Worker reporting and owner notification loop

Actual worker-specific receipts feed the existing durable event store. `operations-monitor-model.mjs` distinguishes worker heartbeat, source-specific item/feed failures, approval holds and prerequisite failures. A successful HTTP check, event-stream keepalive, cron wrapper or unrelated publication cannot make a worker healthy or close its failed item. Unknown/missing/stale evidence alerts. Orange means a documented cadence is approaching its limit; red means missing/stale/failed/held proof. TALC unverified automation is an evidence gap, not an invented technical outage. EyeSpyR's database/provider confirmation remains pending until actual creation is verified; no duplicate project/purchase is permitted.

Read-only detection and the visible status panel use retained worker events even if the new alert store is unavailable. Retained failures are queried separately from latest successes so reloads cannot lose an unresolved feed. Generic aggregate source-discovery events do not prove all failed feeds recovered. Producers should use distinct task/item identity and emit matching verified recovery. Source/publication event IDs, blocked-since, freshness, owner, cause, impact and next action are preserved and sanitized. Private synthetic incidents never enter the public projection.

The additive `portfolio_monitor` schema stores stable incident lifecycle, monitor runs, notification outbox and append-only delivery attempts. SQL exact scope is in `schema.sql`. It was tested using isolated PGlite0.3.14; the initial production mutation was rejected and then directly approved by the owner. No runtime delete, anon/authenticated schema access, new roles, site activation or publisher changes follow from this schema.

`api/operations-monitor` is disabled unless server-only MARKETT_DURABLE_MONITOR_ENABLED=true. GET accepts only the existing CRON_SECRET bearer; POST requires the existing operations-audit HMAC identity and existing task scopes. POST modes are bounded reconcile or clearly labelled private synthetic failure/recovery test. No shared actor key map is changed. Existing actor-domain limits are respected; missing scopes are explicit. Native schedule activation must follow the real production test, not a successful wrapper/configuration.

Owner delivery uses a server-only approved HTTPS receiver configured by MARKETT_ALERT_WEBHOOK_URL, MARKETT_ALERT_WEBHOOK_TOKEN and MARKETT_ALERT_DESTINATION. The receiver must return delivered=true and an opaque deliveryId only after actual owner delivery. HTTP200 alone, HTTP202 queue acceptance, local Codex ACTIVE settings, a stored outbox row or a successful monitor run are not delivery proof. Acknowledgement is a separate opaque receipt and does not recover the underlying incident. Every unresolved blocker remains in each monitor report until the affected operation is verified repaired. No fake acknowledgement or synthetic outage may be published.

Current exact destination is a local Codex voice chat; the available app tools expose no independent cloud-callable ingress for that chat. Existing five-minute local heartbeat settings do not establish independent delivery. The current production environment has no alert receiver URL/token/destination. The smallest existing cloud transport candidate is repository-native GitHub notifications using Actions' repository-scoped managed identity with issues:write, with actual owner acknowledgement as delivery proof. That alternative is not connected and cannot silently substitute for the required chat destination. No new paid notification provider is assumed.
